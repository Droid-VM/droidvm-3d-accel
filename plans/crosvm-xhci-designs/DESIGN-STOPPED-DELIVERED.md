# crosvm xHCI: a cancelled transfer that had already moved the whole TD is a completion, not a stop

Repo: /root/gitrs/DroidVM/DroidVM_wip_usb/crosvm_build/external/crosvm, branch wip/usb, HEAD d849baf. Read scratchpad/m6b/uas/stream-restart-analysis-2.md FIRST (the us-level ETW reconstruction of run6 cold2 attach #3) and stream-restart-analysis.md.

## Finding (run6, crosvm d849baf)
12 attaches; the only stop where both stream rings truly parked with cancelled TDs stranded 16.1 s DESPITE the doorbell restart working (proof: the second Stop Endpoint completed code=1, which needs a Running endpoint that only a valid doorbell sets). Mechanism (~75%): the stop's USBDEVFS_DISCARDURB hit the silent stream's data-IN URB at the moment the warm device delivered that tag's whole 256-byte IU; the reap came back -ENOENT (Cancelled) WITH the data (actual_length = full TD length). crosvm treated it as a stop: silently rewound ring 3, no event; Windows (given the one Stopped event for the OTHER stream) kept the URB pending, re-pointed AT the TD and re-armed it; the restarted ring re-executed the TD -> a fresh URB asking for data the device already sent and will never resend -> UASPStor SRB timeout 16 s -> TASK MANAGEMENT IU -> re-drive. Clean stops differ only in fate class: every cancelled TD either completed 0x0 (discard raced a full delivery and reaped status 0 -> dc1e0bf completes it) or 0xC0000120 via the Stopped event, after which UASPStor re-drives the SCSI exchange. Hardware never hits this: a Stop freezes the transfer (link flow control) and a restart RESUMES it.
Alternative (~25%): the restarted ring never re-executed (no code path found); the debug! lines below discriminate it on the next device run.

## Decision (Fable 5.1)
1. xhci_transfer.rs, XhciTransfer::on_transfer_complete, TransferStatus::Cancelled arm: compute the TD's data length (sum of transfer_length() over Normal / Data Stage / Isoch TRBs -- the same walk stopped_at uses); if bytes_transferred >= td_len && td_len > 0 && !on_drained_ahead_ring(): treat as a normal completion -- send the ordinary IOC/ISP transfer events (the backend's Cancelled arm already copied the data into the guest buffer), do NOT record_stopped (no rewind, no claim consumed; the ring parks past the TD through the existing take_stopped()==None path). Partial delivery (0 < bytes < td_len) stays a Stopped/rewind as today (document the residual in the commit body). Drained-ahead rings unchanged (e5eece2 gate). d849baf stays.
